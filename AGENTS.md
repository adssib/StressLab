# AGENTS.md — StressLab

Instructions for any coding agent working in this repo. (`CLAUDE.md` imports this file.)

## The project

**StressLab** measures how far one Go + Postgres API on one small Azure VM can go, then changes
**one thing per step** and measures again. Act 1 squeezes the single machine; Act 2 scales out
onto Azure managed services and Kafka; step 10 pushes past the limit. It's a **solo portfolio
project**: a finished, honest result matters more than coverage — but the method has to hold up
to a senior reviewer.

## Working agreement

- **One step per turn.** A step is one module or one ROADMAP item — not a feature, not a layer.
  Write it, run it, show what it produces, then **stop** and wait.
- **Never write a file and its consumers in the same pass.**
- **Run it after every step.** A step is done when its output has been seen, not when the file
  exists.
- **If a step turns out bigger than expected, split it and say so.**
- **Ask before** adding a dependency, changing anything in the SPEC's held-fixed list, or reaching
  for a component from a later step.
- **Verify, don't assert.** Library behavior, Azure prices, quotas, SKUs and limits are checked
  against the real source (a quick spike, the docs, the Retail Prices API) before they go into
  code or docs — with the date checked. Leave `_TBD_` rather than guess.
- **End every reply with "What I need from you"** — a short numbered list — when a decision is
  pending.

## Invariants — breaking these breaks the project's claim

1. **One switch per step.** A run varies exactly one config switch from the SPEC's ladder table.
   Everything on the held-fixed list stays fixed; changing it invalidates comparison with every
   earlier run.
2. **Handlers never change.** A step adds behavior by **wrapping** the `Store` (cache, read router,
   events) or adding middleware behind a config switch. With every switch at its baseline value,
   the code path is step 0's.
3. **One store operation per request** for E1–E4. Auth never touches the store.
4. **No number without a run.** Every number in the README or the write-up comes from a committed
   file in `runs/`. The README's results are generated by CI, never typed.
5. **Conformance before benchmark.** A step that fails the conformance suite is not load-tested.
6. **Observability is the same in every run** — exporters, scrape interval, trace and profile
   sampling, and the logging policy.

## Azure safety

- **Only ever deploy to Azure for Students** (`2b812a74-f9f4-4848-b71d-eb7898148ce3`). The same
  login also sees a **university production subscription** — never touch it. Run
  `az account show` before anything that creates resources; Terraform pins the subscription ID.
- **Budget first, teardown always.** The budget alert exists before any other resource. Nothing
  runs outside a session. Price every new service before it's created.
- **Quota is 6 vCPUs** in East US, and step 0 uses all 6. Anything more needs a decision first.
- **Never commit secrets.** The repo is public. Connection strings, the token signing key and
  Azure credentials live in environment variables or Terraform-managed secrets.

## Code

- **Go**, standard layout: `cmd/` for binaries (`api`, `seed`, `consumer`, `stresslab`),
  `internal/` for everything else. Standard-library HTTP; no web framework.
- Match the surrounding code. Structured logs via `log/slog`. Errors wrapped with context.
- Config switches live in `config.yaml`; every switch defaults to its baseline value. Secrets come
  from environment variables only.
- **Tests where a silent regression would corrupt a result:** the conformance suite, seed
  determinism, the limit search logic, `stresslab compare` refusing mismatched runs, the run
  record schema, the guards. No coverage target; no testing trivial code. When you find a bug,
  add the test that would have caught it.

## Docs

- **Docs change with the code**, in the same commit. Say which docs you updated, or why none
  needed it.
- **SPEC is the contract.** If code and SPEC disagree, say which one is wrong — don't drift.
- **Present tense means it exists or is decided**; later things are marked with their step.
- **No ADRs.** Decisions go in the SPEC's *Decided* / *Open decisions* tables; what a step
  changed and found goes in its run record's `notes`.
- **Diagrams are Mermaid**, inline, and must render on GitHub — render-check before committing.
  Prefer a diagram to a paragraph when explaining how something fits together.
- **Keep the README short:** hook, nav, results table, two diagrams. Detail belongs in `docs/`.

## Git

- **Solo repo: commit and push straight to `main`.** No branches or PRs.
- Commit only when asked. Subjects are short and lowercase (`docs: …`, `api: …`, `infra: …`).
- One logical change per commit.
- Code written by an agent carries a co-author trailer.
- **Never** put an agent session ID or session link in anything that gets pushed.
